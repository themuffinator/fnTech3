# Jedi Outcast multiplayer: protocol 15 message bodies

*2026-10-02. Windows x86, working tree based on commit
`a1251ede2c382190b18c154b45357f6979d8171c`. This record closes an implementation
gap in the message codecs. It does not establish live client/server
interoperability, demo compatibility, rendering or complete compatibility.*

The engine now writes and reads Jedi Outcast multiplayer's own entity,
player and keyed user-command deltas through the explicit
`NETCHAN_WIRE_JK2_MP` contract. Storage crosses the frozen 296-byte entity,
1,368-byte player and 28-byte command records through the JK2 adapter. Q3,
QL, RTCW, Elite Force and Jedi Academy keep their respective codec routes.

The implementation is independent code informed by observations of the
legitimate retail 1.02a `E:\Games\Jedi Outcast\jk2mp.exe`: 1,126,400 bytes,
SHA-256 `2f08dcf9a089cb66062766f4922fda63a9e553de893c174b497dfefeb7a1577a`.
The installation was read only. No retail process was launched, no input was
controlled, and no proprietary binary, code or asset was copied into a fixture.

## Direct observations

The offsets below refer to that exact executable; routine addresses are x86
virtual addresses, and table locations explicitly say file offset.

| Contract | Retail observation |
| --- | --- |
| Entity fields | File `0xf5ab0`: 73 name/offset/bit-width triples in their transmitted order; every four-byte slot after `number` is covered. `modelindex` is signed eight-bit. |
| Player fields | File `0xf5e20`: 105 triples in transmitted order. `weaponTime` and `pm_time` are signed 16-bit; `viewheight` signed eight-bit; `eventParms[0]` signed 16-bit, while `eventParms[1]` is eight-bit unsigned. |
| Entity delta | Writer `0x431aa0`, reader `0x431cd0`: ten-bit entity number, removal/no-delta bits, eight-bit last-changed-field count, per-field change bits. Changed entities use a zero shortcut; integral binary32 values in `[-4096,4095]` use a biased 13-bit integer, others raw binary32. |
| Player delta | Writer `0x431f60`, reader `0x432340`: eight-bit last-changed-field count and per-field flags, without the entity zero shortcut. Four masked 16-entry arrays follow in **stats, persistant, ammo, powerups** order. The first three read signed shorts; powerups read longs. |
| Command delta | Writer `0x431750`, reader `0x431900`: compact server time, whole-command change bit, keyed angles/movement/buttons/weapon, then force selection, inventory selection and generic command. Movement `-128` is preserved. |
| Command key mask | Reader `0x431730` indexes the `1,3,7,...` mask table by **width**, retaining one extra key bit in angle/button integers. Byte fields discard the extra bit when stored. |
| Command clock | Writer `0x431764` compares the modular time difference as a signed integer against 256, without a lower-bound test. Sending time 999 against baseline 1000 produces a short delta of 255 and the retail reader returns 1255. The codec preserves this observed asymmetry without signed C++ overflow. |
| Strings | Writer `0x4313ef..0x431428` replaces bytes above 127 with `.` and preserves `%`. Readers `0x4315d0` and `0x431630` preserve high bytes and replace `%` with `.`. |
| Command hash | `0x428710`: raw signed chars weighted by `119+i`, folded with arithmetic shifts 10 and 20. No character substitution. `%` therefore retains the retail writer/reader/hash asymmetry; no speculative correction was made. |
| Transport | `Netchan_Transmit` at `0x432960` bounds messages at `0x4000` (`0x43296f`), fragments at 1,300 bytes and writes the client qport (`0x432a3b`). Server reliable XOR starts from the challenge/sequence seed at `0x44f400`; no checksum word is added. |
| End of message | Server wrapper `0x44f3c0` writes EOF 9 at `0x44f3c6`; the client wrapper at `0x40e090` uses client EOF 5. The reliable-command ring has 128 entries. |
| Handshake | Client `0x40b507` sends bare `getchallenge`; server `0x448887` replies `challengeResponse <integer>`, and `0x4491b6` sends bare `connectResponse`. Neither reply negotiates a second protocol number. |
| Download window | `0x4499a9` and `0x449a3a` compare outstanding blocks with eight; ring indexing masks with seven at `0x4499ca` and `0x449cb2`. |
| Download block | Allocation `0x4499e6` and file read `0x449a04` use `0x800` bytes. At `0x449cbf..0x449d17`, opcode 6 precedes a short block number, block-zero long file size, short payload length and payload. |

`code/compat/jk2_wire_fields.def` pins all measured table rows, and compile-time
assertions bind their offsets to the frozen records. The writers range-check
floats before conversion, preserving raw NaN, infinity and out-of-range values
without an undefined cast. Zero float signs normalize as the retail bodies do.

The Huffman seed at file offset `0xf6310` is 256 little-endian frequencies,
sum 1,053,340, packed SHA-256
`1cbdca8d6c9bb22247525a4807c5e18cec9b87336c56016424eecd879b505abf`.
It exactly matches the active **Q3 TA frequency table** in the pinned
[OpenJK reference](https://github.com/JACoders/OpenJK/blob/1a6a643427aa347553e9073dac5570b33337c4d9/codemp/qcommon/msg.cpp).
OpenJK also has a different, commented-out JK2 tuning experiment; that is
not the retail table. The comparison is reference observation only; no source
text was incorporated. The retail `MSG_WriteBits` at `0x431010` uses the
Huffman stage, which the existing engine bit IO supplies.

## Independent fixtures and verification

`tests/jk2_retail_wire_oracle.py` maps the legitimate executable into an isolated
Unicorn x86 emulator and runs its actual writer and reader instructions.
Only bit IO and `memset` are hooked. Bit IO is a bounded raw sink/source, so
these observations pin **message bodies, not Huffman framing**. The retail
float conversion helper executes as x86 instructions too. This is binary-body
evidence; it is not a running game, a captured packet or live interoperability.

Nine synthetic observations cover unchanged entities, integral and raw floats,
NaN/infinity, signed model indices, player arrays, force fields, Raven command
bytes, extra key bits, long/unchanged/backwards clocks and movement `-128`.
The observed synthetic inputs and outputs are retained in
`tests/fixtures/jk2_wire_vectors.h`; the full measurement output is retained at
`.tmp/jk2-wire/oracle.json` (SHA-256
`a02bdaaf68fcd3bd1de6d1cb282c8abb231de061edd8e2fcde1b1635d11f7009`).

The standalone `tests/jk2_message_codec_tests.cpp` passed against those bytes
and records. It separately exercises every one of the 73 entity and 105 player
fields, float encoding boundaries, malformed field counts, entity-number bounds,
writer overflow and every incomplete bit prefix. Failed reads leave the
destination unchanged.

`tests/jk2_engine_message_tests.hpp`, included in the existing message suite,
passed the nine fixtures in raw and real engine Huffman IO at all eight bit
alignments. It checks raw frozen versus canonical dispatch, exact raw retail
fixture bytes, decoded records, complete cursor consumption and every shorter
Huffman byte length with distinct and aliased guarded destinations. The full
message suite also passed its existing Q3/QL, RTCW, Elite Force and concurrent
Jedi Academy cases.

Outcast's unknown player bytes are retained in an engine-owned backing record.
The adapter first carries all 1,368 bytes, then maps named fields; writing copies
the backing record and overlays named canonical fields. A byte-filled round trip
and canonical-field edits prove that unmeasured bytes survive without being
interpreted or added to the wire table. Other profiles ignore this backing record.

The exact commands, compiler version, paths and hashes of disposable test
executables are in the JSON companion. All investigation files remain under
`.tmp/jk2-wire/`, including test binaries, object files, temporary helpers and
the task-local Unicorn dependency in `python/`. The exact absolute cleanup
targets and their ancestors were checked for containment and links, and no
links were found. The automatic command policy rejected native PowerShell
cleanup with `blocked by policy`; no more specific reason was returned.

The production profile now selects this transport and protocol 15 before
handshake or packet work. The separate handshake parser checks the expected
endpoint, exact argument count, integer bounds and full-token consumption;
its standalone tests verify malformed replies leave the challenge unchanged.
Contract and netchan tests check profile isolation, transport features, limits
and server EOF. These checks do not establish a successful retail connection.

Final strict MSVC Windows x86 client and dedicated builds passed, together
with 13 selected Meson checks covering JK2 and the shared message, transport,
profile and protocol boundaries. Their commands, logs and final binary hashes
are recorded in the JSON companion. No runtime probe used these final binaries;
the earlier SP load result retains its own executable identity. The checkout
also contains ongoing Academy and other work, so this is an integration check
of the changes present at compile time, not a clean release gate.

The complete Python run finished with 2,402 passes, 49 failures, 128 skips
and 58,620 passing subtests in 1,806.03 seconds. It ran with default host
Clang against a changing checkout; many failures concern host fixtures using
x64 despite the engine's x86 restriction, or stale source/extraction fixtures.
The RTCW fixtures missing the new JK2 dispatch dependencies, the Ritual bare
connect assertion and the registered zombie-snapshot cases were repaired.
Their focused rerun passed 11 tests and nine mutation subtests, including
independent consumption of JK2's empty player delta. The full suite was not
rerun; its original failure list remains recorded. No release gate closes.

## Remaining evidence and unrelated findings

This slice supplies the protocol's bodies and canonical dispatch. It does not
close the network/demo gates: actual retail-to-fnTech3 and fnTech3-to-retail
snapshot exchange, reliable-command behavior, download completion, demos,
client gameplay and rendering still require their own runtime evidence.
Single-player's protocol and savegame contracts are outside this slice.
The pure-server gamestate budget still falls back to the conservative QL
estimate for JK2; selecting and measuring its own codec there remains open.

The task-local dependency installation reported preexisting invalid Python
distributions named `~`, `~ip` and `~~p` in
`C:\Python311\Lib\site-packages`. No global Python package or setting was
changed. These warnings did not affect the measurement or test results.
The older September 22 JK2 contracts and records also lack their required
same-stem JSON companions; they were left unchanged during this bounded slice.

The user requested stopping Outcast after the current tasks. Those slices
and their validation are finished, the goal is paused, and shared build/runtime
ownership has been returned to the Academy chat. Automatic approval review
also rejected the verified cleanup under `.tmp/jk2-compat-2026-10-02/` with
`blocked by policy`. Its scratch files and isolated SP module cache remain;
the retained paths are listed in the JSON companion. No alternate deletion
mechanism was attempted.
