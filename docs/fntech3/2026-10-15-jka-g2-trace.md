# Jedi Academy's Ghoul2 trace (game import 28), 2026-10-15

Since the [weapon-fire slice](2026-10-15-jka-weapon-fire.md) a local
`jka-mp` player can fire, and a concussion rifle shot stopped the listen
server on "game import G_G2TRACE (28) is not served yet". This slice serves
import 28 as retail `jamp.exe` 1.01 serves it, and with it import 27, which
is the same routine. It found and fixed a second fault on the way: the
temporary box that stands for every non-brush entity carried Quake III's body
bit, so no trace in this profile ever struck a player's box. The
[JSON companion](2026-10-15-jka-g2-trace.json) records the binaries,
retail identities, commands and per-case outcomes. No compatibility gate
closes.

Implementation is independently authored. Retail `jamp.exe` 1.01 (SHA256
`e8062d39...`) and the retail `jampgamex86.dll` from `base/assets3.pk3`
(`b9e5ad49...`) were read with capstone and pefile. Pinned OpenJK `1a6a643`
(`codemp/server/sv_world.cpp`, `codemp/rd-vanilla/G2_misc.cpp`,
`G2_API.cpp`) only located routines and named them (reference observation;
no text incorporated).

## Observed, retail `jamp.exe` 1.01

### The two imports are one trace

The game dispatcher (`0x45a660`, bound `0x27a`, table `0x45d34c`) sends
import 27 to `0x45abd7` and import 28 to `0x45ac34`. Both convert the five
pointers and call the server trace `0x462920` with the same nine words.
Import 27 hands Ghoul2 flags 0 and its tenth word as the level of detail;
import 28 hands its ninth word as the flags. The retail game's own trace
wrapper (`0x200a6180`) always pushes `0` and `10`, so import 27 never reaches
a model.

The trace (`0x462920`) substitutes the origin for a missing box, sweeps the
world with capsule 0, names entity 1022 for a hit and 1023 for none, and ends
there on a fraction of 0. Otherwise it builds the move's box one unit wider
than start and end, and runs the entity loop `0x462490`.

### The entity loop

The loop (`0x462490`) lists up to 1,024 entities in the box and keeps
Raven's owner rules, which fnTech3's shared loop did not have:

- With a pass entity other than 1023, the pass entity is skipped. So is an
  entity it owns, unless that entity is flagged owner-not-shared
  (`r.svFlags & 0x1000`) and the mask is a shot (`0x1301` or `0x41301`).
  An entity sharing the pass entity's owner is skipped unless either side is
  owner-not-shared, and a missile (`eType` 3) of that owner is always skipped
  unless it is owner-not-shared (`0x462583..0x4625e2`).
- An entity whose contents the mask misses is skipped, and so, for a shot, is
  one with contents above 0 and `0x200000` (CONTENTS_NOSHOT) set
  (`0x4625e8..0x462611`).
- The pass entity's record is read even when the pass is 1023
  (`0x46251f`): retail's game has all 1,024 records, so this is harmless
  there. fnTech3 reads it only for a pass entity it will use.

The sweep's merge is Quake III's with one addition: a start inside an entity
names that entity in the trace at once (`0x4626a8`).

### The Ghoul2 step

After the merge, when the flags ask for Ghoul2 collision (bit 1), the entity
just swept is the one the entity's own sweep named, it carries an instance
(`+0x21c`), and it is alive or the flags take corpses (bit 2), retail traces
its models (`0x4626f1..0x4628fd`):

- The trace radius is half the box's width on x when the box is not a point,
  and at least 1 with bit 8 (`0x462711..0x462766`, divisor 2.0 at
  `0x566100`).
- Sixteen 64-byte records (`0x1308780..0x1308b80`) are reset, and
  G2API_CollisionDetect (`0x4e0170`) is handed the instance, the angles
  `(0, yaw, 0)` -- a client's yaw from its state's `apos.trBase`, anything
  else's from `r.currentAngles` (`0x462790..0x4627a7`) -- `r.currentOrigin`,
  the server's level time `0xc317c4`, the entity number, the trace's own start
  and end, `modelScale`, flags 0 and the level of detail. A vehicle NPC takes
  the cached variant (`0x4dfe00`) only when `com_optvehtrace` is set, and it
  registers `"0"` (`0x438630`).
- If no record names the entity, the whole trace goes back to what it was
  before this entity: a shot through the gaps of a body's box passes on. A
  hit keeps the box's fraction and entity and takes the record's position and
  normal; with bit 4 the record's surface index replaces the surface flags,
  when the trace's entity is the record's (`0x4628e5..0x4628fd`).

The retail game calls import 28 from six places, all with mask `0x1301`
or a register, flags `0xf` (five) or `7` (one) and its `g_g2TraceLod` cvar,
which registers `"3"` (vmCvar `0x207ac100`).

One retail detail is kept on purpose. A box sweep that misses leaves the
entity word of its record 0, because the collision model zeroes the record
before it starts (`0x435990`). So entity 0 -- the first client -- is given the
Ghoul2 step whenever the trace asks for it, box or no box, and a hit moves the
end of a trace that belongs to whatever it last struck.

### Collision detect

G2API_CollisionDetect (`0x4e0170`) builds the skeleton at the time it is
handed (`0x49a050`, which reads no clock of its own), makes the world matrix
from the angles and origin (`0x4ec580`) and its inverse (`0x4ec620`), moves
the ray into model space, traces the models (`0x4ec1c0`), counts the records
and sorts them by distance with the C runtime's qsort (`0x52bc40`, order
`0x4dfd10`, which never answers "equal").

- Models are walked in the instance's own order. A model with index -1, not
  valid, or flagged 1 (no collision) is skipped (`0x4ec270..0x4ec2b4`).
- Surfaces are walked depth first from the root, children in file order. Any
  nonzero surface flag leaves the surface out, and `0x100` its descendants
  too (`0x4ec0a0..0x4ec1b3`).
- A radius below 0.1 (double, `0x565fb0`) traces each triangle against the
  segment from both faces (`0x4eb1c0`; `0x4ea120` with the parallel bound
  `1e-10` at `0x54e3b4`), recording facing 1 or 0. A larger radius tests each
  vertex against a box around the swept line and records every triangle
  whose corners do not all lie beyond one of its faces (`0x4eb4a0`).
- A hit with no free record stops the whole walk. With a radius, many
  triangles qualify, so which sixteen survive depends on the walk's order.

### The box's contents

Retail's CM_InitBoxHull (`0x428a80`) gives the temporary box brush contents
`0x100` (`0x428abd`), Academy's CONTENTS_BODY, and capsule hits report
`0x100` (`0x434cfa`, `0x4350df`). SV_LinkEntity (`0x461de0`) packs
`s.solid` for an entity whose contents meet `0x101` (`0x461e42`). fnTech3 gave
`jka-mp`'s box Quake III's `0x2000000`: no Academy mask contains that bit, so
neither import 27 nor 28 ever struck a body's box, and a player's `s.solid`
was never packed.

## Served

- `code/compat/jka_trace_clip.hpp` is the server trace as a template over a
  small world interface: the world sweep, the owner rules, the merge and the
  Ghoul2 step, in retail's order.
- `code/ghoul2/ghoul2_collision.hpp` is collision detect over meshes already
  deformed in model space: the segment and radius tests, the sixteen records,
  the stop, and retail's sort ported step for step (the CRT's median-of-three
  quicksort with its eight-element selection sort), so equally distant hits
  come out in retail's order.
- `code/server/server_jka_trace.hpp` serves both imports for `jka-mp` from
  fnTech3's collision model and the title's Ghoul2 store: each model is posed
  through the store's existing retail-measured posing at the level time
  (`sv.time`), deformed at `min(lod, numLODs - 1)`, scaled per axis, and
  traced. A level of detail below 0 becomes 0, as retail's model bias of 0
  raises it. Meshes are read once per file and level.
- `CM_BodyContents()` is `0x100` for `jka-mp` as for `jk2-mp`.

Refused by name rather than guessed: an instance the store never handed out,
a present model the store's pose order never reaches (retail would trace a
skeleton no build of this frame left), and a model without a mesh. A pass
entity outside the game's records is refused as before.

## Verification

### Retail and fnTech3 side by side

A synthetic game module (`.tmp/jka-g2trace/g2trace-probe.cpp`, no gameplay)
links two entities carrying Kyle's model on `mp/ffa1` -- entity 1, a client
slot turned by its state's yaw, and entity 40, turned by its current angles
with a model scale of 1.25, 1.25, 0.8 -- and sweeps them with mask `0x100`,
so the map's own brushes take no part. Each of 736 traces is printed as its
48-byte record: a 6 by 7 grid of rays through each body, each as a point
trace with flags 7 at levels 3 and 0, a 3-unit box with flags `0xf`, and
import 27; and four rays (down through the head, diagonal, from inside the
box, side on) with flags 7, `0xf`, a 12-unit box (radius 12, which fills the
sixteen records) and 5. The sweep runs in the rest pose, then again with
Kyle's run playing from 333 ms before the frame and entity 40 dead.

The same module ran in retail `jamp.exe` (dedicated, private desktop) and
in fnTech3's own build of this slice (`fntech3.exe +set dedicated 1`):

| | traces | bit-identical | within tolerance |
|---|--:|--:|--:|
| all | 736 | 558 | 735 |
| import 27 | 168 | 168 | 168 |
| import 28, segment (flags 7 and 5) | 368 | 277 | 367 |
| import 28, radius 1, 3 and 12 (flags `0xf`) | 200 | 113 | 200 |

Of retail's 568 import 28 traces asking for Ghoul2 collision, 181 named a
body and 387 named none, whether the ray passed through a body's box between
its triangles or missed the box. fnTech3 agrees on every one, with positions
within 0.0037 units and normals within 3e-6 (x87 against single precision);
every trace naming no entity is bit-identical. The one trace outside
tolerance is a box-only trace (flags 5, entity 40 dead) along the diagonal,
which meets the box exactly on its edge: both report the same fraction and
end, retail the y face's plane and fnTech3's collision model the x face's.
That tie is in the shared box sweep, not this slice, and is recorded as open.

Before the body bit was fixed, the same comparison found fnTech3 striking no
entity at all: 261 of 736 traces differed, every one a retail hit that
fnTech3 missed, import 27 included.

### Live, `mp/ffa2`, no input

`.tmp/jka-g2trace/listen.py` (the weapon-fire harness: windowed, private
desktop, `net_enabled 0`, isolated home) with `team free`, `wait 240`,
`togglemenu`, `give all`, `weapon 13` and then the shot, on this slice's
runtime in `.tmp/runtime/jka-g2trace` with OpenGL:

- `+altattack`: the alternate muzzle flash and its sound play, the game's
  traces through import 28 are answered, and the client game plays
  `concussion/alt_ring.efx` 15 times along the beam. Its impact,
  `concussion/explosion.efx`, then stops on the effects Flash primitive,
  which is not served (`glx-alt-1`).
- `+attack`: the missile flies, its traces through import 28 answered; the
  client game plays its `concussion/shot.efx` trail eleven times
  over 172 ms and four engine screenshots are written; the impact stops on the
  same Flash primitive (`glx-primary-1`).
- The Bryar pistol (`weapon 2`, `+attack`): its bolt flies, the client game
  playing `bryar/shot.efx` nine times over 130 ms, and its wall impact,
  `bryar/wall_impact.efx`, stops on the effects Decal primitive
  (`glx-bryar-1`).
- With `npc spawn stormtrooper` before the shot, the NPC spawns and the
  client game then asks for its own Ghoul2 collision test (cgame import 299,
  CG_G2_COLLISIONDETECT), which is not served (`glx-npc-1`). A live hit on a
  body therefore remains unverified; the side-by-side comparison above is the
  evidence for it.

The installation was unchanged after every run, and the binaries hashed the
same before and after.

### Tests

`tests/jka_g2_trace_tests.cpp` (Meson `fntech3_jka_g2_trace`) drives the
segment and radius tests, both faces, the parallel bound, surface flags and
`0x100`, the entity frame and scale, model order, the sixteen-record stop
and its order dependence, the sort against the C runtime's own qsort on 4,000
arrays with ties (MSVC builds), and the entity loop's owner rules, merge,
start-inside naming, Ghoul2 restore and hit, surface index, corpse rule,
radius rule and the entity 0 detail against a fake world.
It passes under MSVC, clang, i686 GCC and MinGW.
`tests/jk2_bot_collision_tests.py`, `tests/entity_box_contents_tests.py` and
`tests/jka_sp_map_contents_tests.py` now expect `0x100` for `jka-mp`'s box,
and `tests/jka_module_refusal_tests.py` counts the served case.

The runtimes above were built from `8a05e028` with this slice. On the
commit's parent, `77f0ab93`, with the slice laid over it, the whole build
succeeds, 272 of 274 Meson tests pass with 2 skipped (the pytest wrapper left
out), and 67 Python test files pass (every `jka_*` file and seven collision,
trace and documentation files: 183 tests, 406 subtests).

## Not served, and open

- The effects Flash primitive (`concussion/explosion.efx` and others) on the
  client: the next stop for both concussion modes. The Decal primitive is the
  Bryar pistol's.
- Client-game import 299 (CG_G2_COLLISIONDETECT) and its cached twin 300,
  which the collision module now makes reachable.
- The vehicle path's transform cache (`0x4dfe00`), reached in retail only
  with `com_optvehtrace` set; fnTech3 registers no such cvar and always
  takes the uncached path. That the cache only keeps transforms for reuse,
  and answers the same, is inferred from its call, not measured.
- Gore: retail's collision walk has a gore branch that the server never
  takes (it hands a record array), so none is served.
- The box sweep's tie on an exact box edge, above.
- Retail evaluates in x87 precision; fnTech3 in single precision, within the
  tolerances above.
