# Jedi Academy effect decals, 2026-10-15

The [entity effect slice](2026-10-15-jka-entity-effect.md) left a
first-person Bryar pistol shot flying until its wall impact,
`effects/bryar/wall_impact.efx`, stopped on the effects Decal primitive.
This slice serves that primitive. Retail's Decal case hands the decal to its
renderer's own decal pool, the same entry the client game's import 205
reaches; fnTech3 keeps the same pool beside its effects, cuts each mark with
its own mark clipper and draws it through its own polygon path. A
first-person Bryar shot now leaves its scorch mark on the wall in GLx and
Vulkan. The [JSON companion](2026-10-15-jka-decal.json) records the binaries,
retail identities, commands and outcomes. No compatibility gate closes.

Implementation is independently authored. Retail `jamp.exe` 1.01 was read
with capstone. Pinned OpenJK was used only to name routines (reference
observation; no text incorporated).

## Observed, retail `jamp.exe` 1.01

### CreateEffect's Decal case

CreateEffect (`0x407c40`) switches on the primitive family minus one
through the table at `0x40b5e8`; entry 6, Decal, is `0x40ac7e`
(`0x40ac7e..0x40ada4`). It:

1. draws the size start (template `+0x1dc..+0x1e0`), the alpha start
   (`+0x1c4..+0x1c8`) and the rotation (`+0x104..+0x108`), each with the
   range draw `0x444230` when the ends differ;
2. picks one handle from the media list at `+0x48` (`0x405d50`);
3. calls the renderer's AddDecalToScene through the engine's copy of the
   renderer export table (`[0x8af084]`) with eleven words: the shader, the
   spawn origin (CreateEffect's frame `+0x40`), the spawn axis's first row
   (`+0x5c`), the rotation, the RGB start that the shared code drew before
   the switch (GetRGB `0x406de0` into `+0xa8`, skipped only for Sound,
   FxRunner and CameraShake at `0x409853..0x409875`), the alpha, alpha fade
   1, the size as the radius, and temporary 0;
4. tests the flag word at `+0x98` for `0x40000` (`ghoul2Decals`). Set, it
   draws the size again (`0x405d90`), picks another shader, and `0x405cc0`
   writes `{shader, size, origin, direction}` to the client game's shared
   buffer and calls client-game export 17 (`CG_G2MARK`).

No other template word is read: the life, velocity, curve ends, parms and
curve words, and every other flag word stay in the template.

### The renderer's decal pool

The engine's `[0x8af084]` is a copy of the renderer export slot at
`0x1309bc0`, which `GetRefAPI` fills with `0x4ab6c0`. The client game's
trap dispatcher calls the same slot for import 205 (`0x412cc6..0x412cfc`).

- **AddDecalToScene** (`0x4ab6c0`): returns at once while `r_markcount` is
  zero or less and the decal is not temporary; a radius at or below zero is
  a fatal error (`0x4ab6f9`). It normalizes the direction (`0x443dd0`),
  takes a perpendicular (`0x4440e0`), turns it by the orientation about the
  normal (`0x4433f0`) and crosses the two; the corners are the origin -/+
  radius along the second and third rows; the texture scale is the double
  0.5 over the radius. The projection is the caller's direction, not the
  normal, times -20 (`0x56655c`). R_MarkFragments (`0x4a6cf0`) is asked for
  at most 384 points and 128 fragments. The colour is each component times
  255, truncated (`_ftol`). A fragment of more than ten points keeps its
  first ten (`0x4ab9a0`); each point's texture coordinates are 0.5 plus its
  offset from the origin along the second and third rows times the scale.
  A temporary decal is drawn at once (`0x4ab090`); otherwise each fragment
  becomes a kept record (`0x4aba96..0x4abaf9`): time, shader, colour, its
  vertex count at `+0x20` and its vertices at `+0x28`.
- **RE_AllocDecal** (`0x4ab5b0`): two pools (normal and fading) of 500
  records of `0x118` bytes. A pool whose total exceeds `r_markcount` is
  cleared whole. The head record, if in use, is pushed out: if it was made
  in an earlier scene, the records after it made in the same scene go with
  it. The head then advances, wrapping at `r_markcount`.
- **RE_FreeDecal** (`0x4ab530`): a normal record pushed out is copied into
  the fading pool with its time set to now and its fade time to now + 1000.
- **R_AddDecals** (`0x4abb20`), called from RE_RenderScene (`0x4abf32`)
  unless the view has `RDF_NOWORLDMODEL` (`0x4abf1f`), after the scene's
  time is set (`0x4abdfa`): a changed `r_markcount` clears every record;
  each pool is walked from its head; a fading record draws with alpha
  `(1 - t / 1000) * 255` (`0x56600c` is 1000.0), truncated, until its
  second is over, and is then freed; a kept record draws as it is.
- **RE_ClearDecals** (`0x4ab500`) is reached only by import 201
  (`0x412c71`) and R_Init (`0x4a2cc0`).
- `r_markcount` is registered by R_Init with `"100"` and flag 1
  (`CVAR_ARCHIVE`, `0x4a24fe`).

The shader every installed Decal names, `gfx/damage/burnmark4`
(`assets1.pk3` `shaders/marks.shader`), takes its colour and alpha from the
vertices (`rgbGen vertex`, `alphaGen vertex`), so the fade shows.

## Implemented

- `code/compat/jka_effect_play.hpp`: the Decal family is served. Its shader
  list is the template's; other media in it, an empty list, or a size start
  at or below zero refuse by name. `ghoul2Decals` refuses by name
  ("effects ghoul2Decals is not served yet"), since client-game export 17 is
  not served. Every other field the Decal case does not read is inert;
  unknown curve words still refuse as they do for every family. The spawn
  keeps the drawn size, rotation, RGB start and alpha start.
- `code/compat/jka_decals.hpp`: the pool and the square as measured above.
  Fn bounds: `r_markcount` above 500 counts as 500 (retail would index past
  its records), a direction without length or values beyond the effects
  adapter's bounds press nothing (retail would build not-a-number corners),
  and colour and fade bytes clamp where retail's would wrap.
- `code/client/client_jka_cgame_decals.hpp`: the pool lives in the client,
  registers `r_markcount` (`"100"`, `CVAR_ARCHIVE`) for `jka-mp` alone, and
  takes each decal at the last world scene's time. The effects host's
  Decal case hands it the record retail's case hands its renderer.
- `code/client/client_jka_cgame_host.hpp`: every world scene (no
  `RDF_NOWORLDMODEL`) draws the pool at the scene's own time before it
  reaches the renderer; import 201 clears it; it is cleared with the client
  game too, as retail's renderer pool is cleared with the renderer at each
  map load.

### Fn presentation (invariant 11)

The mark is cut by Fn's own mark clipper (`re.MarkFragments`, the shared
renderer path the Quake III-line client games use) and drawn through Fn's
polygon path (`re.AddPolyToScene`), so it takes the active renderer's
shader stages, polygon offset, fog and dynamic lighting in GLx, Vulkan and
RTX alike. The retail data it adapts is the decal's shader, square,
colour, the pool's count and the fade. No retail-exact presentation option
is kept beside it: the pool rule, the projection and the fade are the
contract this slice pins.

  reaches the same pool; the retail client game calls it only for its own
  impact marks under `cg_marks 2`.
- Temporary decals: no Decal case or measured caller asks for one.
- RTX captures: this slice's export built the GLx and Vulkan renderers only.
