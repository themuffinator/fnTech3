# Jedi Outcast's MP3 sounds, 2026-10-08

fnTech3 registered its MP3 codec for neither Jedi Outcast profile, so a
`.wav` name never reached its `.mp3` and nearly every Outcast sound failed to
load: the open audio blocker the
[UI local sound record](2026-10-08-jk2-ui-local-sound.md) found. This record
pins how both retail engines find a sound's file and play MP3, registers the
codec for `jk2-sp` and `jk2-mp`, and loads Outcast's sounds by its own rule:
`<name>.wav` first, then `<name>.mp3`, whatever extension the game asks for.
Every one of the installation's 8,126 MP3 files decodes through Fn's decoder,
and live, without input, the multiplayer menus' sounds, a console sound and a
music track load from the files retail plays and play through both of Fn's
mixers. The [JSON companion](2026-10-08-jk2-mp3-sounds.json) holds every
address, count, command line and run result. No gate closes.

## The installation

**Observed** (both paks, read with Python's `zipfile`):

- `sound/` holds 8,297 files: 7,987 MP3, 309 WAV and one text file;
  `music/` holds 139 MP3. No name exists as both a `.wav` and an `.mp3`, and
  no file name has two dots.
- Every MP3 is MPEG-1 Layer III at 44.1 kHz: the 7,987 sounds mono, the 139
  tracks stereo, 6 hours of audio in all. 7,971 of them end in Raven's ID3v1
  tag with `#UNCOMP` and `#MAXVOL`; the 139 tracks and 16 sounds have none.
- The WAVs are mono: 264 at 22,050 Hz, 13 at 44,100, 30 at 11,025 and 2 at
  5,500 (27 of the 309 are 8-bit).
- Voices sit in `sound/chars/` (2,895 files) with German and French
  recordings beside them in `sound/chr_d/` (2,358) and `sound/chr_f/`
  (2,356). These counts exclude ZIP directory entries, which the initial
  inventory had counted as files; the installation was recounted on October 9.

## How retail finds a sound's file

**Observed** (`jk2mp.exe` and `jk2sp.exe`, read with Capstone; no retail code
is incorporated). Addresses are multiplayer's, then single player's;
functions carry the names the engines' own strings give them, or the usual
id Tech names where they give none. Both engines resolve a name the same way:

1. **The extension is dropped when the sound is registered.** `S_FindName`
   (`jk2mp.exe` 0x45cc00, `jk2sp.exe` 0x423930) cuts the name at its first
   `.` (`COM_StripExtension`, 0x434220 and 0x41f1d0, which stops at the first
   dot anywhere in the path) before hashing, comparing and storing it. So
   `x.wav`, `x.mp3` and `x` are one sound with one handle.
2. **`<name>.wav` is read first, then `<name>.mp3`.** Multiplayer's
   `S_LoadSound` (0x45f020, 0x45f050) writes `"%s.wav"` (0x4fddf0) on the
   stored name; single player's (0x42a8e0, 0x42a910) appends `.wav` to a name
   with no three-letter extension, which the stored name never has. The file loader
   (0x45f520, 0x42adb0) reads that `.wav`, and only when it is absent
   overwrites the last three characters with `mp3` (0x45f6dd, 0x42af7c) and
   reads again. **A `.wav` beside an `.mp3` always wins, whichever the module
   named.**
3. **Voices follow the language.** A name containing `chars` is first tried
   with `chr_d` when `s_language` is `DEUTSCH` or `chr_f` when `FRANCAIS`,
   `.wav` then `.mp3`, and falls back to the English `.wav` then `.mp3`. Both
   engines register `s_language` as `english`, archived (0x401; 0x45ca1a,
   0x423350).
4. **The file that loaded picks the decoder.** An `.mp3` is checked
   (`MP3_IsValid`, 0x45fe00) and sized (`MP3_GetUnpackedSize`, 0x45fe40),
   which takes Raven's `#UNCOMP` tag where there is one (0x45ff90) and
   measures the file otherwise. Anything else is read as a WAV, and a stereo
   WAV is refused (0x45f25f, 0x42ac70).
5. **Large MP3s stay compressed.** `MP3Stream_InitFromFile` (0x4600c0,
   0x40a0a0) keeps an MP3 compressed and decodes it while it plays when its
   size plus `s_mp3overhead` is below its unpacked size plus 2,304 bytes;
   `s_mp3overhead` is 31,756, archived (0x460090, 0x40a070). Otherwise the
   MP3 is unpacked at load. Multiplayer applies the rule to every MP3 sound,
   and at the default it keeps 7,863 of the installation's 7,987 compressed
   (computed from the rule and each file's size and tag); single player
   applies it only to voices under `sound/chars/` (0x42b010). Each channel
   playing a compressed sound takes its own copy of the decoder's state
   (`S_StartSound` copies 0x1a03 words from the sound, 0x45d336).
6. **A looping sound may not be compressed.** Multiplayer's
   `LoopSound_ChannelInit` (0x45d750, string pushed at 0x45d7ba) and single
   player's `S_AddLoopSounds` (0x424bcb) drop the game (`ERR_DROP`, "Cannot
   use streamed MP3 files here for random access") for one. The
   installation keeps to that: all seven looping sounds the 15 multiplayer
   maps and the multiplayer client game name are WAVs (an eighth,
   `sound/weapons/rocket/missileloop.wav`, ships in neither format), and the
   nine MP3 loops of single player's maps lie outside `sound/chars/`, which
   single player never keeps compressed.
7. **Music.** `S_StartBackgroundTrack` (0x45e2c0) appends `.mp3` to a name
   with no extension and requires that file (0x45e200), with no fallback:
   "Unable to find music file" stops the music. An `.mp3` name streams
   through the MP3 decoder, anything else through the WAV reader (0x45e380;
   single player appends `.mp3` in both places, 0x4273b5 and 0x4275ed). When
   multiplayer's intro ends, it looks for `<loop>.wav` first (0x45eac1 to
   0x45eae4) and otherwise restarts the loop through the `.mp3` rule.
8. Retail mixes at `s_khz` 22 (0x45c9a8, 0x423256), and a compressed
   sound's decoder is started at the mixer's rate (0x4601bb). Its default
   sound is a generated `*defaultsound` (0x45ce04).

**What the installation asks for.** Scanning the multiplayer modules, every
map's entities, the text data, both executables and single player's game
library for `sound/` and `music/` names finds 378 names that ask for a `.wav`
whose only file is the `.mp3`, 724 that name their `.mp3` and 147 their
`.wav`, and 9 that ask for an `.mp3` whose only file is the `.wav`: the
effects files' and two maps' `sound/ambience/spark1.mp3` to `spark6.mp3`,
single player's `sound/weapons/force/heal.mp3` and `speedloop.mp3`, and a
cinematic's `sound/effects/hologram_loop.mp3`. Retail plays those nine from
their `.wav`. All 27 music names resolve to an `.mp3`: 18 are given without
an extension, 9 with `.mp3`.

## fnTech3 before

`S_CodecInit` (`code/client/audio/codecs/snd_codec.cpp`) registered the MP3
codec for Elite Force, the Ritual titles, Medal of Honor and Academy only. In
both Outcast profiles a `.wav` name therefore failed once its `.wav` and
`.ogg` were absent, and an `.mp3` name matched no codec, so its extension was
never cut: `spark1.mp3` was looked for as `spark1.mp3.wav` and failed even
though `spark1.wav` exists. A music name without an extension tried `.wav`
and `.ogg` only.

## The change

- `S_CodecInit` registers the MP3 codec for both Outcast profiles. The list
  is WAV, MP3, Ogg Vorbis, as for the other MP3 titles; every other
  profile's list is unchanged.
- `S_CodecLoad`, which both backends use to load every sound effect, loads an
  Outcast sound as `<name>.wav`, the name cut at the first `.` of its file
  name, so the codec list reads the `.wav`, then the `.mp3`, then Fn's Ogg
  Vorbis: retail's order, whatever extension was asked for. A name too long
  to take `.wav` loads as given. Elite Force's German voices and every other
  profile load exactly as before.
- Music keeps Fn's stream lookup: the name as given, or WAV, MP3 and Ogg
  Vorbis for a name with no extension. For every music name the installation
  uses, that is the file retail plays.

**Differences recorded, not reproduced:**

- Retail gives `x.wav`, `x.mp3` and `x` one handle; Fn registers each name,
  so two names of one file are two handles to the same sound.
- Retail keeps large MP3s compressed and decodes them per channel at its 22
  kHz mixer rate. Fn decodes every sound whole at load, at the file's own
  44.1 kHz, and its mixers resample. So no Fn sound is ever compressed, and
  any MP3 can loop where retail would drop the game; no retail data reaches
  that refusal (step 6).
- Retail cuts a name at the first `.` anywhere in its path; Fn cuts at the
  first `.` of the file name, so a folder with a dot in its name, which
  breaks the name in retail, still loads.
- Music: retail looks only for `<name>.mp3` when no extension is given, and
  multiplayer's loop restart for `<loop>.wav` first; Fn tries `.wav`, `.mp3`
  and `.ogg` and falls back when the named file is missing. They choose
  differently only where a `.wav` and an `.mp3` of one music name both exist,
  which no installed music does.
- **Foreign voices are not implemented.** Fn registers `s_language` for Elite
  Force only and never loads `chr_d` or `chr_f`, so a German or French
  setting plays the English voices. Open below.
- Fn's Outcast profiles register Quake III's `sound/feedback/hit.wav` as
  handle 0, which Outcast ships in neither format, so handle 0 stays Fn's
  generated fallback tone, as retail's is a generated sound of its own.
- Diagnostics retail never prints: with `developer` set, Fn notes
  `Sound fallback: x.wav -> x.mp3` for each MP3 a `.wav` name loads, and the
  legacy mixer `x is not a 22kHz audio file` for each 44.1 kHz sound; the
  legacy mixer also prints `music file x is not 22k stereo` for every track.
  Both mixers resample, so these are notes, not faults.

## Decoding every MP3

The committed `tests/fixtures/stvef_mp3_probe.cpp`, Fn's frame walker and
minimp3 configuration, decoded every `.mp3` in both paks, copied under `.tmp`
and deleted afterwards. **All 8,126 decode completely**, and Fn's decoded
mono byte count reproduces **7,970 of the 7,971** Raven `#UNCOMP` sizes. The
exception is `sound/weapons/force/drain.mp3`: one stray byte sits between its
93rd and last frame and its ID3v1 tag, and minimp3 then returns no samples
for that frame, so Fn plays 92 frames, 26 ms short. Raven's size counts all
93. This was the result of this slice alone. The subsequent
[last-frame correction](2026-10-08-mp3-last-frame.md) retains that frame and
reproduces all 7,971 sizes.

## Live, without input

Each run starts an fnTech3 client on an unswitched private desktop: windowed,
`developer 1`, `net_enabled 0`, no input injected, no server, an empty config
in its own home. The `jk2-mp` client opens its main menu and runs the retail
UI's own commands from one startup cfg, as the UI local sound record does:
`ui_openmenu quitMenu` plays the focus sound `menuroam.wav` on channel 6, and
closing `videowarningMenu` plays `button1.wav` on channel 0. The console then
runs `play sound/weapons/saber/saberon.wav sound/ambience/spark1.mp3`,
`music music/mp/duel` and `s_list`. With OpenAL each step is followed by
`s_alDebugDump`s; the legacy runs list voices with `s_show 2`. The private
desktop mutes the client, so nothing was heard; `s_musicvolume` is 0.05 only
because Fn does not decode a silent track.

**Observed** (fnTech3, after):

- `menuroam.wav` and `button1.wav` load from their `.mp3` (the developer
  line names each fallback) and play: OpenAL voices in the `local` class at
  gain 1.00, dry 1.00 and no send, in 7 and 9 of the 12 dumps after their
  steps; `s_show 2` lists them at 127/127 for 17 and 21 updates.
  `saberon.wav` loads `saberon.mp3` and plays the same way (8 of 8 dumps,
  108 updates).
- `spark1.mp3` loads `spark1.wav` directly, as retail does, and plays (8 of
  8 dumps, 24 updates).
- `s_list`: `menuroam` mono 44,100 Hz 182 ms, `button1` 261 ms, `saberon`
  1,645 ms, `spark1` 303 ms (OpenAL); 4,032, 5,760, 36,288 and 6,703
  samples at the legacy mixer's 22,050 Hz. Each matches the file's own
  length; `menuroam`'s 8,064 samples are Raven's 16,128-byte tag.
- `music music/mp/duel` opens `music/mp/duel.mp3`: OpenAL reports it as the
  background track with 4 buffers queued, the legacy mixer as its background
  file.
- Before: all four sounds are `missing` (OpenAL) or 0 samples with `could
  not find ... - using default` (legacy), `spark1.mp3` included, and both
  mixers print `couldn't open music file music/mp/duel`.

**Single player.** A `jk2-sp` client initializes its sound system and then
stops: `CL_InitUI` refuses the profile ("Jedi Outcast's single-player menu
boundary is open") before any startup command runs, so no sound is started
there. Single player's registration and name rule are the shared code the
unit test runs for both profiles.

## Presentation (invariant 11)

Outcast's sounds play through Fn's mixers: the OpenAL backend's classes,
distance model, occlusion, rooms, HRTF and limiter, or the legacy mixer, the
retail-exact option. Fn decodes each file whole at its own rate; no retail
decoding rate, compressed playback or mixer is reproduced.

  `S_CodecInit`, `S_CodecGetSound`, `S_CodecLoad` and both name helpers for
  every profile, with and without MP3: both Outcast profiles now register
  MP3, and `S_CodecLoad` reads `<stem>.wav`, `.mp3`, `.ogg` for ten names (an
