# Linux i686 RTX raster and native RT checkpoint

The existing Linux i686 client and RTX renderer now have bounded Q3 runtime
evidence under private Xvfb with Mesa lavapipe (software Vulkan). Both artifacts
are verified ELF32 Intel 80386 files. This round changes no engine code and
does not rerun the automated suite.

| Probe | Effective image size | Observed result |
| --- | --- | --- |
| RTX raster, `rtx_rt_mode 0` | 1280×960 | Pure admission, snapshots, `vid_restart`, two engine screenshots and normal client/server exits |
| Native RT required, mode 2 and `rtx_rt_require 1` | 1280×960 | Active ray-tracing pipeline, native dispatch/copy marker, one engine screenshot and normal exits |
| Native RT required, same-renderer fast restart | 320×240 | Native dispatch before and after `REF_KEEP_WINDOW` shutdown, two engine screenshots, continued snapshots and normal exits |

The native probes report `active=ray_tracing_pipeline (2), require=1` and
`shading=native_rt`. The dispatch marker is emitted after the renderer records
its ray dispatch and copies output to scene color; it distinguishes this path
from raster fallback. All screenshots were inspected. World textures and HUD
remain readable, but native RT output has visible noise. This is execution and
bounded lifecycle evidence, not a visual-quality or parity pass.

The first native probe's intended 320×240 configuration arrived through an
`exec` file after initial renderer startup, so its actual image was 1280×960.
The second supplies window mode at startup and confirms 320×240 in renderer
logs and both images. Both probes are windowed. Input grabbing is disabled;
homes and displays are isolated, and no user input or OS screenshots are used.

Khronos validation-layer cleanliness remains unverified. An attempt to install
`vulkan-validationlayers:i386` fails because the configured Ubuntu repositories
do not provide that package; they offer an amd64 candidate. Engine log messages
containing the word “validation” are dispatch diagnostics, not evidence that
the Khronos layer ran. No validation package was installed by this attempt.

The [evidence record](evidence/2026-09-08-linux-rtx.json) pins artifact and source
identities, commands, configuration, installation identity, execution markers,
logs and screenshot hashes. Linux source lineage remains the modified
`b5776c9` checkout with the previously recorded corrections, not a fresh clean
build. Retail assets and screenshots remain local.

This establishes software native-RT execution for Linux i686 Q3 only. It does
not close the shared Windows x86 Q3/QL native-RT gate, establish hardware RT
performance, or supply the missing native Linux QL cgame/UI modules. Validation
layers, longer lifecycle stress, full visual parity, audio/service interaction
and broader merger gates remain open. Existing image/font warnings and hosted
CI's account billing/spending blocker remain unresolved.
