# RTX renderer work round — 2026-09-06

This round adds native scene transport and Q3 material coverage, fixes observed
raster and Vulkan lifecycle defects, and establishes bounded runtime evidence.
**Q2RTX parity and full Q3/QL compatibility remain open.** The detailed
[feature comparison](RTX_Q2RTX_PARITY.md) distinguishes implemented paths from
missing capabilities; the [compatibility ledger](COMPATIBILITY.md) owns the
shared-profile gates.

## Implementation

- Native ray generation now follows a bounded sequence of scene-radiance rays,
  with sampled diffuse/GGX reflection and transmission, Fresnel/total internal
  reflection, PDF weighting, geometric origin offsets, and finite output guards.
  `rtx_rt_indirect_bounce` accepts 0–4; reflection/refraction can request one
  continuation when the diffuse-bounce budget is zero. Radiance and shadow hit
  and miss stages share the same payload layout.
- Static base-texture/lightmap collapse preserves independent lightmap UVs,
  image identity and intensity. Native admission also recognizes both explicitly
  collapsed vertex lighting and implicit engine-generated `LIGHTMAP_BY_VERTEX`
  materials. It does not treat arbitrary authored vertex colors as irradiance.
  The packed RT vertex is 80 bytes with compile-time and executable layout tests.
- Optional dynamic geometry uses posed weighted MDR triangles, replacing its
  box approximation. MD3 extraction uses explicit LOD0/frame interpolation;
  supported model skins can contribute to secondary radiance and shadows while
  primary model color remains raster. Personal shadow casters are retained;
  first-person/depth-hacked/no-shadow entities are excluded from this path.
  Dynamic signatures include material/color/shape changes and reject unsafe
  floating-point quantization. Dynamic BLAS remains disabled by default.
- Temporal reconstruction compares reprojected depth with the previous camera,
  handles hit/miss disocclusion and sky translation, rejects reactive dynamic
  hits/reflections, and invalidates history when transport controls change.
  It still lacks previous skinned-object motion and advanced denoising.
- Raster batches reject shadow-caster-only surfaces before their equal-sort
  fast path. This fixes the recorded Q3 black polygons. Uniform allocation is
  bounded and transactional. Both RTX and Vulkan track logical geometry-buffer
  capacity separately from the larger Vulkan memory allocation requirement.
- Descriptor attachment updates now occur after all shadow sets are recreated;
  packed depth/stencil transitions include both aspects for shadow images too.
  Cleanup tolerates absent device/function table, descriptor pool and active
  command state following partial initialization.
- A separately named Windows x64 Q3-only diagnostic build enables native probes
  on this machine. `-Dq3-only=true` is explicit, rejects QL before filesystem
  startup and does not relax the default shared x86 release contract. See
  [build instructions](../../BUILD.md).

The Q2RTX feature inventory and PBRT sampling equations informed independent
design, not an implementation-text import. References are credited in
[CREDITS.md](../../CREDITS.md). No proprietary modules/assets were added.

## Remaining work and unrelated finding

The largest renderer gaps are polygonal emissive-light extraction and importance
sampling, authored PBR texture inputs, physically integrated liquids/volumetrics,
motion-aware diffuse/specular denoising, temporal upscaling, and broader animated
and material-fallback validation. Baked lightmaps plus native transport are an
artistic hybrid and can overlap lighting contributions. Primary portals, models,
particles, complex shaders and translucent materials still use raster ownership.
Shared x86 native Q3/QL evidence is blocked on this driver. The feature matrix
also records environment/photo-mode/performance and lower-priority multi-GPU gaps.

Separately discovered: the inherited on-disk `R_LoadMDR` parser in
[tr_model.c](../../code/rendererrtx/tr_model.c) has incomplete source-buffer
validation for offset/weight traversal. This round's new MDR helper bounds
the already loaded/decompressed model; it does not repair the upstream file
parser. That parser hardening remains a separate open issue.
