fnTech3

Unified source port for id Tech 3

fnTech3 is one engine distribution -- one client, one dedicated server and three renderer modules -- for Quake III Arena, Quake Live, Return to Castle Wolfenstein, Wolfenstein: Enemy Territory, Star Trek Voyager: Elite Force, Star Wars Jedi Knight: Jedi Academy, Star Wars Jedi Knight II: Jedi Outcast, American McGee's Alice, Heavy Metal: F.A.K.K.2 and Medal of Honor: Allied Assault.

1. Introduction

fnTech3 selects one immutable game profile -- the contracts of one game or game mode -- before the filesystem, network, game modules, renderer or any optional service starts. Each game keeps its own module interfaces, protocol, demos, saves, file formats and gameplay. How the engine presents it -- renderers, spatial audio, input, console and screenshots -- is fnTech3's own, fed with that game's data.

Quake III Arena

quake3 (q3): enabled in every build. One profile spans the releases: 1.32 (protocol 68) and ioquake3 (71) play, host and record; original 1.29 to 1.31 servers and clients (66, 67) connect in both directions; recordings from 1.11 on play back. The February 1999 IHV Test is a separate q3-ihv profile for Windows x86 dedicated-server probes in builds with -Dq3-ihv-development=true, and the public Q3Test releases of 1999, 1.02 to 1.08, are the q3test profile for Windows x86 developer builds with -Dq3test-development=true.

Quake Live

quakelive (ql): enabled in every build. The retail client modules are 32-bit Windows libraries, so the client runs on Windows x86.

Return to Castle Wolfenstein

rtcw-sp and rtcw-mp: experimental; developer builds with -Drtcw-development=true. Both modes share one installation and one executable.

Wolfenstein: Enemy Territory

wolfet (et): experimental; developer builds with -Dwolfet-development=true run its client and server. See the jump-sound correction and validation limits.

Star Trek Voyager: Elite Force

stvef-sp and stvef-mp (Holomatch): experimental; developer builds with -Dstvef-development=true. Single player needs Windows x86. Input corrections and diagnostics are available; live gameplay input remains under validation.

Jedi Academy and Jedi Outcast

jka-sp and jka-mp: experimental developer probes with -Djka-development=true; retail MP menu startup, limited animated UI geometry, client skin/animation and copy metadata, neutral light-style and map distance metadata, cgame menu relay, neutral command values, polygon submission, remote bone/tag queries, owned skeletal scene staging, engine-default models, ordinary-sky views, forward-animation transitions, no-rotation bolts, a captured player-configuration menu, absent ambient-set returns and limited shader-effect lifetimes, empty cleanup and maintained pure admission with clean disconnects in both directions, ordinary/additive scene lights, the Academy text atlas and bounded GLx/Vulkan/RTX demo captures, explicit music preloading, ambient/effect definitions and retail SP Init return. Campaign, complete client rendering and bidirectional retail compatibility remain incomplete.

jk2-sp and jk2-mp: experimental developer probes with -Djk2-development=true; client, campaign and live compatibility remain incomplete.

American McGee's Alice

alice: experimental; Windows x86 developer builds with -Dalice-development=true. Alice runs Ritual's engine rather than a Quake III one.

Heavy Metal: F.A.K.K.2

fakk2: experimental; Windows x86 developer builds with -Dfakk2-development=true. Point fs_basepath at an installed game, not a copy of the disc.

Medal of Honor: Allied Assault

mohaa: experimental; Windows x86 developer builds with -Dmohaa-development=true. Version 1.00, with system86.dll beside MOHAA.exe; fnTech3 loads the installation's copy.

These ten games and sixteen profiles define the project scope. Full compatibility is not yet established for any profile. Build and unit results do not replace runtime and retail-interoperability evidence. The compatibility ledger records the observed results and open gates, and the Games Guide summarizes what each game does today.

This package is engine-only and starts Quake III Arena and Quake Live; the experimental games need a developer build. Supply your own legitimate installation. Retail modules, assets and proprietary runtimes remain there. Release packages exclude the optional proprietary Steam provider and Valve Steam runtimes. Steam services require a separately supplied compatible provider; unavailable services are reported honestly.

2. Features

Capabilities from the engine baselines and fnTech3's own work apply to a game where its guide says so, and must be validated for each profile. Quake Live's WebUI, Steam and Workshop services belong to the Quake Live profile alone.

Unified game compatibility

One immutable profile per process owns the game's installation rules, module interfaces, protocol, demos, saves, file formats and optional services. Adapters convert at every boundary, so one game's structures never reach another's modules or packets.

Fast, modern hardware rendering

Choose between optimized GLx, Vulkan raster and Vulkan RTX renderers in every game with a client, with GPU-cached world geometry, merged lightmaps, reduced rendering overhead and improved depth precision. RTX path traces each map with its own lights.

Modern visual upgrades

Optional HDR rendering and output, MSAA, supersampling, render scaling, anisotropic filtering, bloom, tone mapping, colour grading, per-pixel and shadowed dynamic lights, static map lights, motion blur, lens flares, soft particles, enhanced liquids, an underwater view and per-map fog.

Improved player visibility

Optional player rim lighting, stencil outlines or both in Quake III Arena and Quake Live, with configurable enemy, teammate, team and free-for-all colours, intensity and outline thickness. Cel shading, model outlines and world-edge outlines are also available.

Better modern hardware and OS support

SDL3 video, input and audio, OpenAL, modern graphics APIs, high-resolution and high-refresh displays, borderless/windowed/fullscreen modes, fast Alt+Enter switching, controller hotplugging and each game's own application icon.

Low-latency, configurable controls

Raw mouse input, Quake Live-accurate CPI scaling, signed acceleration, sensitivity caps and angle-history filtering, while retaining classic Quake3e/ioquake3 mouse styles. Modern gamepads and Unicode text input are also supported.

Modern spatial audio

OpenAL and HRTF headphone positioning, surround output, reverb, geometry-based occlusion, shipped audio zones, output-device selection, live device recovery and fallback to the classic software mixer, fed with each game's own sound data.

Major quality-of-life improvements

A scalable console in each game's own font, smooth scrolling, mouse selection, clipboard support, drag-and-drop editing, live command/cvar/map completion, widescreen FOV and HUD correction for every game written for 4:3 screens, minimize hotkeys, focus muting and lower background CPU usage.

Better screenshots, video and streaming tools

PNG, TGA, JPEG and BMP capture, clipboard screenshots, custom filenames, camera metadata, configurable levelshots, watermarks, cube-map capture, arbitrary-resolution output and FFmpeg video piping.

Faster content handling

Quicker startup and map restarts with large PK3 libraries, raised filesystem and map limits, fast redirected downloads and, in Quake Live, automatic handling of server-required Workshop content.

Greater stability and security

Extensive Quake3e and FnQuake3 fixes, bounded parsing of every game's files, demos and packets, lower memory usage, stronger network protection and graceful fallbacks when optional rendering, audio, WebUI or Steam functionality is unavailable.

3. Getting Started

Unpack this package into a folder of its own and point it at your legitimate installation of the game you want to run.

Keep fntech3-pkg.fnz, fnql-web.pak, the fnql_<renderer>_x86 modules and the redistributable libraries beside fntech3.exe and fntech3.ded.exe. The engine package keeps each game's data under its own games/<profile>/<gamedir>/ folder. Upgrade it with the executable; the old FnQL-pkg.fnz layout is no longer read.

Choose the game

Start with +set com_gameProfile quake3 or +set com_gameProfile quakelive, +set fs_basepath "<game installation>" and a separate writable fs_homepath for each game. Add +set r_fullscreen 0 to start windowed. gameList in the console lists every profile and whether this build can start it.

Automatic detection

Without a profile, the engine looks for exactly one recognized installation in fs_basepath, beside the executable, then in the Steam libraries. Two games in one place, or a game whose modes share one installation, need the profile named.

Dedicated servers

Run fntech3.ded with the same explicit profile and a separate home. On Linux the Quake Live server loads the retail qagamei386.so; native Linux clients cannot load Quake Live's Win32-only client and UI modules.

Experimental games

RTCW, Enemy Territory, Elite Force, Jedi Academy, Jedi Outcast, Alice, F.A.K.K.2, Medal of Honor, the IHV Test and Q3Test need a developer build with their option, as the build guide describes. This package refuses them with an explanation.

The selected profile cannot change while the process runs; a mode change relaunches the executable. Startup, module loading, demos, play and retail interoperability must pass each profile's gates before compatibility is claimed.

4. Documentation

Start with the player guides for setup and tuning. Build, compatibility and implementation details live in the technical references; the ones marked as included ship in this package.

  • Display Guide for renderers, display modes, HDR, scaling, anti-aliasing, bloom, lighting, shadows, fog, liquids, lens flares and motion blur.
  • RTX Renderer Guide (included) for requirements, path tracing, fallback behavior, safe settings and troubleshooting.
  • GLx Renderer Guide (included) for the default OpenGL-lineage renderer, diagnostics and troubleshooting.
  • Visuals Guide for player highlighting, colours and outlines.
  • Aspect Handling Guide for widescreen FOV, HUD layout, menus and cinematics.
  • Audio Guide for devices, HRTF, spatial effects, audio zones, each game's sound and troubleshooting.
  • Console Guide for layout, fonts, completion, clipboard use and mouse interaction.
  • Screenshot Guide for formats, filenames, metadata, levelshots, watermarks and cube maps.

Technical and build docs

  • Compatibility ledger (included) for all sixteen profiles, observed evidence, open gates and unified release sign-off.
  • Architecture overview (included) for how profiles, adapters and the shared subsystems fit together.
  • Engine package (included) for fntech3-pkg.fnz and its per-game sidecars.
  • Changelog (included) and release guide (included).
  • Build Guide for compiling fnTech3 and enabling each game's development option.
  • RTX Renderer Contract for the renderer's module boundary, conservative defaults and runtime validation.
  • FnQL baseline documents for the Quake Live profile's WebUI, Steam provider, input and font contracts, and the inherited renderer and audio design notes.
